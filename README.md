# Seelai

> A Flutter mobile assistant that empowers partially sighted users with AI-powered
> vision tools, real-time location sharing, and one-tap emergency support — while
> giving caretakers and municipal social workers the tools to respond.

Seelai is a role-based Flutter application. Partially sighted users get object and
face detection, document text reading with text-to-speech, emergency hotlines, and
location-based assistance; caretakers and MSWD (Municipal Social Welfare and
Development) staff can track patients in real time, manage assistance requests,
post announcements, and monitor system activity.

---

## ✨ Features

**For partially sighted users**
- Object & face detection with on-device TFLite models (`object_detection.tflite`, `face_detection.tflite`)
- Document text reading via Google ML Kit with text-to-speech playback
- Pre-loaded Philippine emergency hotlines (PNP, BFP, MDRRMO, DILG, MSWD, local
  health centers) and one-tap emergency actions
- Real-time location sharing so caretakers can see where help is needed
- Voice and video calls with caretakers (WebRTC), haptics and voice guidance

**For caretakers**
- Patient management, live location tracking and assistance request handling
- Voice/video communication with assigned patients and missed-call alerts
- Notifications for incoming requests and activity updates

**For MSWD staff**
- Dashboard with stats, announcements and urgent alerts
- User and request management, hotline administration (editable hotline list)
- System activity logs and PDF system report export

**Platform / infrastructure**
- Firebase Authentication, Firestore, Realtime Database, Storage and Cloud Messaging
- Google Maps integration for location services and Cloudinary for image storage
- CI pipeline (static analysis + tests) on every push/PR to `main`

## 🚀 Getting started

```bash
# 1. Clone
git clone https://github.com/onetwothird/Seelai-App.git
cd Seelai-App

# 2. Install dependencies
flutter pub get

# 3. Configure Firebase (requires flutterfire_cli)
flutterfire configure

# 4. Run on a device / emulator
flutter run

# 5. Release build (Android)
flutter build apk --release
```

> Versions of every dependency are pinned in `pubspec.lock`. After changing
> `pubspec.yaml`, run `flutter pub get` again.

## 🔐 Environment variables

Runtime configuration lives in `assets/.env` (loaded via `flutter_dotenv`):

| Variable            | Purpose                                   |
| ------------------- | ----------------------------------------- |
| `CLOUDINARY_*`      | Cloudinary credentials for image storage   |
| `ROBOFLOW_API_KEY`  | Roboflow workspace key for subject registration |

Because `.env` is a placeholder in this repository, copy it and fill in real
values **locally** — never commit secrets:

```bash
cp assets/.env assets/.env.local   # or just edit assets/.env locally
```

Firebase credentials are generated by `flutterfire configure` into
`lib/core/firebase_options.dart` and should not be committed with real values.

## 💬 Commit conventions

This repository follows the [Conventional Commits](https://www.conventionalcommits.org)
specification. Every commit is scoped to its changes and written as a meaningful
imperative sentence:

| Type       | When to use                          | Example                              |
| ---------- | ------------------------------------ | ------------------------------------ |
| `feat:`    | New feature, screen, or service      | `feat: add emergency hotlines screen` |
| `fix:`     | Bug correction                       | `fix: resolve crash on scanner start` |
| `refactor:`| Code change without behavior change  | `refactor: restructure location service` |
| `style:`   | UI polish, theming, formatting       | `style: match button colors to theme` |
| `build:`   | Dependencies, builds, platform config| `build: update Flutter dependencies` |
| `docs:`    | Documentation only                   | `docs: add setup and CI instructions` |
| `test:`    | Adding/fixing tests                  | `test: cover object detection service` |
| `chore:`   | Assets, tooling, misc                | `chore: add onboarding illustrations` |
| `ci:`      | CI/CD configuration                  | `ci: run analyze and tests on PR`     |

> One commit per logical change, subject line ≤ ~72 characters, imperative mood.
> The pre-commit hook runs `flutter analyze` to catch issues before they land.

## 🐛 Troubleshooting

- **Missing asset errors** – Confirm the file exists under `assets/` and is
  listed in `pubspec.yaml`, then run `flutter pub get`.
- **Release build failures** – Run `flutter build apk --release -v` for verbose
  output and check that all assets/models used by the code are packaged.
- **Hooks fail on non-Windows machines** – The hook installer uses PowerShell
  (`pwsh`); install PowerShell or temporarily commit with `--no-verify`.
- **Firebase errors at runtime** – Ensure `flutterfire configure` ran and
  `lib/core/firebase_options.dart` matches your project.
